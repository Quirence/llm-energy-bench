# quality-v3: предварительная регистрация проверки качества

Статус: **утверждён владельцем исследования 6 ноября 2026 года**. Документ
фиксируется тегом `quality-v3-prereg` до первого производственного запуска
и далее не меняется. Отклонения записываются отдельным разделом в отчёте, а
не правкой этого файла.

## 1. Зачем нужен эксперимент

Вывод статьи об энергии правильного ответа (`docs/paper-stage-1-thesis.md`,
§§ 6–8) получен анализом после сбора данных на восьми собственных заданиях.
Ответы при `temperature=0` детерминированы, поэтому эффективный объём выборки
качества равен восьми заданиям, а повторы не добавляют информации. Кроме того,
пересчёт сохранённых ответов показал, что во втором эксперименте почти весь
разрыв Llama и Qwen по энергии правильного ответа (10,8–14,1 раза) вызван
нарушением формата: по правильности Llama даёт 0,60, а не 0,075, и разрыв
сокращается до 1,35–1,74 раза.

quality-v3 превращает этот вывод в **подтверждающую проверку на независимом
общепринятом наборе** с заранее заданными гипотезами, правилами оценки и
двумя осями качества: правильность ответа и соблюдение формата.

## 2. Что не меняется

- Замороженные наборы `paper-dataset-v1` и `power-quality-v2`, их выводы и
  теги не изменяются.
- quality-v3 — отдельное исследование с отдельными конфигурациями,
  каталогами прогонов и отчётом. Его данные не объединяются с прежними.
- Повторные прогоны энергии у соавторов не требуются.

## 3. Исследовательские вопросы и гипотезы

**H1 (основная, направленная).** На MGSM-ru в режиме «только ответ» энергия
правильного ответа (ось правильности) у `qwen3:4b-instruct-2507-q4_K_M` ниже,
чем у `llama3.2:3b-instruct-q4_K_M`.
Критерий подтверждения: отношение `E_прав(Llama) / E_прав(Qwen)` больше 1, и
нижняя граница 95% бутстрэп-интервала по заданиям больше 1.

**H2 (направленная).** В режиме «только ответ» доля ответов, нарушающих
формат при правильном значении, у Llama Q4 выше, чем у Qwen Q4.
Критерий: точный тест Мак-Немара на парах «задание — модель», p < 0,05.

**H3 (направленная).** Для обеих Q4-моделей разрыв между строгой оценкой
(правильность и формат) и оценкой правильности на MGSM-ru больше у Llama.
Критерий: разность долей с 95% бутстрэп-интервалом, не включающим 0.

**В1 (исследовательский вопрос, без направления).** Что дешевле на правильный
ответ для каждой модели: ответ сразу или ответ с рассуждением? Сообщаются оба
значения и их отношение с интервалом; заранее направление не предсказывается.

**В2 (описательный).** IFEval: четыре официальные метрики для четырёх
конфигураций и энергия на задание, выполненное по строгой метрике уровня
запроса.

**Проверка правдоподобия, не гипотеза.** Значения IFEval сопоставляются по
порядку величины с опубликованными: Llama 3.2 3B Instruct bf16 — 77,4
(среднее четырёх метрик, 0-shot) [R20]; Qwen3-4B-Instruct-2507 — 83,4 [R19].
Для MGSM опубликовано только значение Llama 3.2 3B — 58,2 (0-shot CoT, все
языки) [R20]; для Qwen3-4B-Instruct-2507 GSM8K и MGSM не опубликованы.
Совпадение чисел не ожидается (см. § 9).

Порог качества 0,75 из прежних экспериментов в quality-v3 **не
применяется**: на общепринятом наборе абсолютное качество малых моделей
ниже, и порог исключил бы все конфигурации. Сравнение ведётся по энергии
правильного ответа и по парным различиям качества.

## 5. Наборы заданий

**MGSM-ru** — русская часть MGSM: 250 задач GSM8K в переводе людьми [Shi et
al., 2022]. Источник: исходный файл авторов `mgsm/mgsm_ru.tsv` в
`google-research/url-nlp`, коммит `4b1e7a43efb517abadd16041e8b47f3be975c76e`,
SHA-256 `6bd30fd2e80c5bac23f566fb4ae0e6a55a19578401fbf9a01fb21beb3645fef8`.
Исходный репозиторий лицензию не указывает; зеркало Hugging Face
`juletxara/mgsm` объявляет CC BY-SA 4.0 (исходный GSM8K — MIT). Проверить
перед публикацией репозитория. В четырёх эталонах (задачи 147, 202, 231,
250) стоит разделитель разрядов (`2,125`); эталоном считается целое число
без разделителя.

**IFEval** — 541 запрос с проверяемыми инструкциями [Zhou et al., 2023].
Источник: Hugging Face `google/IFEval`, ревизия
`966cd89545d6b6acfd7638bc708b98261ca58e84`, файл `ifeval_input_data.jsonl`,
SHA-256 `6a85310ca8ce15eff755aa08a3a4ff931c7e273e7515ebb3c492ea85fd8288f2`,
лицензия Apache-2.0. Используется
**английский оригинал**: только для него существуют официальная программа
проверки и опубликованные значения обеих моделей. Русские адаптации
(ruIFEval и сообщественные переводы) не проверены и в quality-v3 не входят.

Наборы не копируются вручную: `scripts/prepare_quality_v3.py` загружает
зафиксированные ревизии, проверяет SHA-256 и формирует
`prompts/quality-v3-*.jsonl`; источники, шаблоны, подвыборка детерминизма и
хеши файлов записаны в `prompts/quality-v3-sources.json`. Конфигурации —
`configs/quality-v3/*.toml`. Среда: CPython 3.12.10, зависимости из
`requirements/power-quality-v2-windows-py312.lock`.

## 6. Шаблоны запросов

Тексты фиксируются здесь дословно.

**MGSM-ru, ответ сразу** (`mgsm-ru-direct`):

```
{вопрос}

Выведи только ответ — одно целое число без пояснений.
```

**MGSM-ru, с рассуждением** (`mgsm-ru-cot`):

```
{вопрос}

Реши задачу пошагово. В последней строке напиши «Ответ: N», где N — целое число.
```

**IFEval** — исходный текст запроса без изменений.

Отклонение от официальных протоколов: инструмент добавляет в начало каждого
запроса служебную метку кэша (`uuid_stable_slot_prefix_v4`). Она одинакова
для всех моделей и указывается в разделе отклонений статьи.

## 7. Правила оценки

Оценка выполняется отдельным скриптом по сохранённым `outputs.jsonl` после
окончания серии. Встроенная оценка инструмента не используется как
основная.

**MGSM, ось правильности.** Извлекается последнее целое число ответа после
удаления разделителей разрядов (пробел, неразрывный пробел, запятая между
группами по три цифры). Для режима с рассуждением приоритет имеет число из
последней строки вида «Ответ: N». Совпадение с эталоном — 1, иначе 0.
Правило соответствует гибкому извлечению lm-evaluation-harness.

**MGSM, ось формата («строго»).** Режим «только ответ»: весь ответ после
удаления пробелов по краям и одной завершающей точки равен эталону. Режим с
рассуждением: последняя непустая строка ровно `Ответ: N` с правильным N.

**IFEval.** Официальная программа проверки
(`google-research/instruction_following_eval`), четыре метрики: уровень
запроса и уровень инструкции, строго и мягко. Основная метрика формата —
строгая уровня запроса.

**Ручная проверка.** До разметки фиксируется настоящий документ. Два автора
независимо размечают по двум осям: (а) все ответы MGSM, где строгая оценка и
оценка правильности расходятся; (б) случайную выборку 50 ответов MGSM на
модель (seed 42). Сообщаются доля согласия и коэффициент Коэна; расхождения
разрешаются обсуждением, автоматическая оценка остаётся основной, ручная —
проверкой её корректности. Та же процедура применяется к 52 уникальным
ответам прежних экспериментов как отдельный анализ чувствительности.

## 8. План запусков

Ограничение инструмента — 256 слотов метки кэша на модель в одном запуске
(4 прогрева + задания × повторы).

| Блок | Заданий | Повторы | Запусков на модель | Запросов на 4 модели |
| --- | ---: | ---: | ---: | ---: |
| MGSM-ru direct | 250 | 1 | 1 | 1000 |
| MGSM-ru CoT | 250 | 1 | 1 | 1000 |
| IFEval | 541 (3 части: 181/180/180) | 1 | 3 | 2164 |
| Проверка детерминизма | 50 из MGSM-ru (оба режима) | 1 | 1 | 400 |

Порядок моделей внутри серии чередуется. Оценка времени: около 4 ч на одном
стенде. Если при повторе на подвыборке ответы различаются более чем в 2%
заданий, повторы распространяются на все задания, а качество усредняется.

## 9. Анализ

- Доля правильных — с интервалом Уилсона.
- Энергия правильного ответа: `E_прав = Σ E_запроса / Σ правильных` по
  блоку; 95% интервал — парный бутстрэп по заданиям, 10 000 выборок, seed 42.
- Парные различия качества — точный тест Мак-Немара.
- Те же показатели по времени ответа сообщаются как проверка устойчивости, не
  зависящая от точности измерения энергии коротких запросов.
- Поправка на множественные сравнения: Холм — Бонферрони для H1–H3.

Ограничения сопоставимости с опубликованными результатами: квантование GGUF
Q4/Q8 вместо bf16, шаблон чата Ollama, режим без примеров, лимиты
`num_predict`, служебная метка кэша, вероятное наличие GSM8K в обучающих
данных обеих моделей. Совпадение с опубликованными числами не утверждается.

## 10. Что пишется в статье при каждом исходе

- **H1 подтверждена:** вывод об энергии правильного ответа воспроизведён на
  независимом общепринятом наборе; величина эффекта приводится по оси
  правильности.
- **H1 не подтверждена:** прежний вывод сохраняется как результат на
  собственном наборе с явной оговоркой, что на MGSM-ru он не воспроизвёлся.
  Это сообщается в основном тексте, а не в приложении.
- **H2/H3:** при подтверждении — разделение «правильность против формата»
  включается в обсуждение единицы полезной работы (§ 5.3 черновика); при
  неподтверждении — вывод о многословности Llama ограничивается
  собственными наборами.

## 12. Отклонения и решения после начала серии

Раздел добавлен 6 ноября 2026 года, после тега `quality-v3-prereg`. Разделы
1–11 не менялись.

**12.1. Фильтр приватных данных (отклонение от § 4: «изменения кода не
требуются»).** Запуск `quality-v3-ifeval-a-…-20261106T010920Z-965325`
остановлен инструментом после 100 из 724 запросов: в ответе
`qwen3:4b-instruct-2507-q4_K_M` на задание `ifeval-1375` (пример кода) была
строка вида домашнего каталога POSIX, и проверка публичности артефактов
отказалась записывать результат. Исправление: поле `text` (ответ модели)
исключено из этой проверки, все остальные поля проверяются как раньше; тест —
`test_path_like_text_in_a_model_response_does_not_abort_the_run`. Инференс,
телеметрия и расчёт энергии не изменены. Прерванный запуск сохранён и не
используется, ifeval-a выполняется заново целиком. Блоки MGSM-ru и проверки
детерминизма выполнены на коммите `3a5f7c2`, остальные — на коммите,
вносящем этот раздел.

**12.2. Проверка детерминизма превысила порог § 8.** Доля заданий, в которых
ответ на подвыборке отличается от основного прохода (50 заданий):

| Конфигурация | Только ответ: число / правильность | С рассуждением: число / правильность |
| --- | ---: | ---: |
| Qwen Q4 | 18 % / 4 % | 8 % / 4 % |
| Qwen Q8 | 16 % / 6 % | 10 % / 2 % |
| Llama Q4 | 28 % / 2 % | 18 % / 10 % |
| Llama Q8 | 36 % / 8 % | 22 % / 14 % |

Вероятная причина — служебная метка кэша: она зависит от идентификатора
эксперимента и номера слота, поэтому в повторном запуске префикс запроса
другой. Число повторов в § 8 не задано; решение владельца исследования
(принято после просмотра результатов первого прохода, исходя из времени
работы стенда): **3 прохода MGSM-ru в обоих режимах**. Проход 1 — исходные
запуски, проходы 2–3 — конфигурации `mgsm-ru-{direct,cot}-p{2,3}.toml`,
отличающиеся только идентификатором эксперимента. IFEval выполняется одним
проходом: он описательный (В2), а проверка детерминизма проводилась только на
MGSM-ru; это указывается в ограничениях.

Агрегирование трёх проходов, зафиксированное до их выполнения:

- доля правильных и доля строгих — по всем запросам конфигурации (среднее
  по проходам), интервал Уилсона — по числу заданий;
- `E_прав = Σ E_запроса / Σ правильных` по всем проходам; бутстрэп
  переставляет задания вместе со всеми их проходами;
- H2 (Мак-Немар) — по флагу задания «правильно, но формат нарушен»
  большинством (не менее 2 из 3 проходов);
- H3 — разрыв «правильность − строго» по всем запросам, бутстрэп по
  заданиям;
- значения каждого прохода по отдельности сообщаются как проверка
  устойчивости; проверка детерминизма сравнивает подвыборку с проходом 1.

**12.3. Уточнение § 9.** H1–H3 направленные, поэтому в поправку Холма —
Бонферрони входят односторонние p: для бутстрэпа — доля выборок, в которых
отношение не больше 1 (H1) или разность не больше 0 (H3); для Мак-Немара —
точный односторонний p. Двусторонний p Мак-Немара сообщается рядом.

**12.4. Наблюдения во время серии (не меняют план).**

- *Инференс детерминирован при одинаковом запросе.* Два запуска ifeval-a с
  одним идентификатором эксперимента (то есть с одинаковой меткой кэша) дали
  побайтно одинаковые ответы в 100 из 100 общих запросов; повтор
  mgsm-ru-cot-p2 — в 161 из 161. Расхождения § 12.2 вызваны только меткой в
  начале запроса, поэтому три прохода оценивают чувствительность качества к
  служебному префиксу, а не шум GPU.
- *Ложный признак перезагрузки.* Первый запуск mgsm-ru-cot-p2 остановлен
  инструментом на запросе 161: `load_duration` 111 мс при пороге 100 мс
  (у остальных запросов серии не больше 76 мс, 99 % — не больше 8 мс; модель
  оставалась в видеопамяти, версия Ollama не менялась). По правилу инструмента
  запуск повторён целиком, прерванный сохранён и не используется.
- *Источник энергии сменился внутри серии.* Примерно с 00:50 UTC 6 ноября
  счётчик энергии NVML стал давать значения в 1,7–23 раза больше интеграла
  мгновенной мощности, и инструмент перешёл на интегрирование мгновенной
  мощности. До этого счётчик принимался и был примерно на 10 % выше интеграла.
  Поэтому проход 1 MGSM-ru посчитан в основном по счётчику, проходы 2–3 — по
  интегралу; мгновенная мощность и частоты GPU во всех проходах одинаковы
  (около 80 Вт, 2380 МГц). Основной результат — по значениям инструмента;
  как проверка устойчивости `scripts/score_quality_v3.py` пересчитывает

**12.5. Исключение заданий IFEval (отклонение от § 5).** Запуск
`quality-v3-ifeval-a-…-20261106T015626Z-f4f8f3` остановлен на запросе 113:
на задании `ifeval-1880` (статья не длиннее 200 слов, буква c не менее
60 раз) `qwen3:4b-instruct-2507-q4_K_M` начала повторять «c», и Ollama 0.35.0
оборвала генерацию с ошибкой «token repeat limit reached». Эта защита Ollama
не отключается, а инструмент считает ошибку сервера сбоем запуска. Решение
владельца исследования: задание, на котором Ollama обрывает генерацию хотя бы
у одной конфигурации, исключается из набора для всех конфигураций, и часть
выполняется заново. Список исключений с причинами — `IFEVAL_EXCLUDED` в
`scripts/prepare_quality_v3.py` и `ifeval_excluded` в
`prompts/quality-v3-sources.json`; границы частей a/b/c остаются прежними
(по порядку исходного набора). Наборы MGSM-ru при пересборке не изменились.
Метрики IFEval сообщаются по оставшимся заданиям с указанием числа
исключённых; исключённые задания — отказ модели, а не дефект стенда, и это
указывается в ограничениях.
